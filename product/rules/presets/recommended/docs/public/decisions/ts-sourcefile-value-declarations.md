# TypeScript source-file value declarations

Two or more consecutive variable declaration rows in a TypeScript source file may be aligned when every initializer is a simple value and the engine detects exactly the lookup key `v1|typescript|SourceFile|declaration-values|equals>semicolon`. A simple value is a string literal, a number literal with an optional `+` or `-` sign, `true`, `false` or `null`. The scope is `**/*.ts`; the pattern is `DEFINE`. The declaration kind may be `const`, `let` or `var`, and the row may be exported. Execution order and all non-whitespace tokens must be preserved. Arrow functions, regular expressions, compound expressions, calls, arrays, objects, template literals, bigint literals, `as const`, type annotations, rows mixing these with simple values, including a type annotation or comment on only one row, other AST containers and other axis combinations are outside this approval.

The positive example `ts-sourcefile-value-declarations-positive` records the approved three-row transformation. The engine enforces the initializer boundary by reporting a run as `declaration-values` only when every row qualifies; the wider `declaration-equals` key stays unapproved. A single declaration is outside the rule and must remain unchanged. In `ts-sourcefile-value-declarations-single-row-counter`, the padded after form has verdict `bad` because automatically rewriting a single row violates that boundary; this is not a general style judgment about manually written whitespace.

Frequency evidence: this shape is justified by the first-run path, not by measured frequency. It occurred in 0 of 196 fixable groups across 220 non-test TypeScript files of two public repositories measured on 2026-11-03.

A human maintainer approved this exact scope, the positive example and the excluded boundary on 2026-11-03. The public receipt uses the anonymous role `maintainer`; it does not grant approval for additional rules. The linked short synthetic examples are provided under CC0-1.0.
