# 실험 프로토콜 — 사전 판정(과제 A)에 적합한 모델 설정

상태: 초안, 사전 등록 전 · 날짜: 2026-09-30 · 관련: `docs/research/model-eval.md`, `docs/reviews/2026-09-30-codex-protocol-review.md`

이 문서는 결과를 보기 전에 확정하고, 확정본의 SHA-256을 커밋해 **사전 등록**한다. 등록 뒤의 변경은 모두 "변경 기록"(10절)에 남긴다.

## 1. 연구 질문

과제 A(표 유형 하나의 전·후를 보고 판정 다섯 가지 중 하나를 JSON으로 내기)에서, **허용 기준을 만족하는 가장 싼 설정은 무엇인가?**

결론의 범위는 실험 수단에 묶인다(3절). API로 실험하면 "모델·강도 설정"에 대한 결론이고, CLI로 실험하면 "그 CLI·버전·설정 조합"에 대한 결론이다. 두 실험을 섞어 해석하지 않는다.

## 2. 단계

| 단계 | 목적 | 결론으로 말할 수 있는 것 |
|---|---|---|
| **0. 판정 지침** | 판정 다섯 가지의 정의, `unsure` 처리, 이견 조정 절차를 고정 | — |
| **1. 파일럿** | 판정 기준과 본시험 설계가 실행 가능한지 확인, 표본 수·허용폭 산정 | "실행 가능하다/아니다"만. **어떤 설정이 최고라고 말하지 않는다** |
| **2. 본시험(확증)** | 사전 등록한 가설 검정 | "기준을 만족하는 가장 싼 설정" |
| 3. 후속 | 프롬프트 실험(예문 유무), 정책 실험(올리기 사다리) | 각자 별도 등록 |

프롬프트 효과(예문 유무)와 올리기 사다리는 모델 비교와 섞지 않고 **별도 실험**으로 한다.

## 3. 실험 수단과 동일 조건

**수단:** 이 제품이 사전 판정을 **어떻게 부를지**에 맞춘다. 제품이 API를 부른다면 API 직접 호출로, CLI를 부른다면 그 CLI로 실험한다(결정 필요 — 11절).

**동일 조건은 문서가 아니라 실행기가 강제한다.** 실행기(`scripts/eval.ts`)는 실행마다 **매니페스트**를 남기고, 조건이 어긋나면 실행을 거부한다.

| 매니페스트 칸 | 강제 방식 |
|---|---|
| 프롬프트 바이트와 SHA-256, 템플릿 버전 | 같은 항목·같은 프롬프트 조건이면 해시가 같아야 함 |
| 모델 id, 강도, 최대 출력, 시간 제한 | 설정 표에서만 읽음 |
| 도구·CLI·SDK 버전 | 실험 중 버전이 바뀌면 중단(자동 업데이트 차단 확인) |
| 작업 폴더 내용 해시 | 과제 파일만 있어야 함 |
| 전역 지시 파일·메모리 | 있으면 **실행 거부**, 또는 격리된 설정으로 실행. 격리할 수 없으면 그 사실을 기록 |
| 도구 사용·세션 상태 | 끔(판정에 도구가 필요 없음) |
| 출력 스키마 | 공급자 기능으로 강제(Codex `--output-schema`, Claude 구조화 출력) |
| 순서와 시드 | 항목마다 설정 순서를 시드로 섞고 기록 |
| 캐시 | 입력·캐시 읽기·캐시 쓰기·출력을 나눠 기록, 차가운/데워진 캐시 표시 |
| 원시 요청·응답 | 저장 |

**고정할 수 없는 것(명시):** 공급자 쪽 무작위성, CLI의 숨은 시스템 지시, 실험 중 모델 업데이트, 공급자의 `seed` 지원 여부. 앞의 둘은 반복으로 분포를 보고, 모델 업데이트는 실험 기간과 응답의 모델 식별자를 기록한다.

**조정자 분리:** 실험을 띄우는 Claude 세션은 채점하지 않는다. 채점은 정답과 대조하는 결정적 코드만 한다.

## 4. 항목(표본)

- **단위:** 코퍼스 유형 하나(대표 사례 전·후).
- **표집:** 판정별로 층화한다. 드문 판정(`different-role`, `missing-kind`)은 **일부러 더 뽑는다.** 과표집한 결과는 그대로 배포 분포의 성능으로 읽지 않고, 5절의 배포 분포로 **가중해** 해석한다.
- **분할:** 조정용 세트(판정 지침과 프롬프트를 다듬는 데만 씀)와 **한 번만 쓰는 보류 세트**. GUIDE 예문과 겹치지 않게 유형·저장소 단위로 나눈다.
- **정답:** 블라인드 사람 판정(모델 이름과 AI 제안을 가림). 판정자 1명이면 탐색 수준으로만 해석한다(9절).

## 5. 결과 변수

**배포 분포:** 본시험 전에 코퍼스 전체의 유형 빈도로 "실제로 만날 판정 분포"를 정해 둔다.

| 구분 | 변수 |
|---|---|
| **주 판단 기준** | 배포 분포로 가중한 **정확도**와 **판정별 재현율**, 특히 놓치면 위험한 판정(`different-role`, `missing-kind`)의 **최소 재현율** |
| 보조 | 균형 정확도, macro-F1, 혼동표 |
| 민감도 분석 | Cohen κ, Gwet AC1 (순서 없는 범주이므로 가중 κ는 쓰지 않음) |
| 운영 | 무효 JSON 비율, 완료 항목당 비용(가격 정본), 지연(중앙값·p90) |
| 안정성 | 같은 항목 반복 간 불일치(후속 실험) |

## 6. 가설 (본시험, 파일럿 후 확정)

- **H1 비열등성:** 경량 설정(예: gpt-6-luna low)의 가중 정확도는 기준 설정(gpt-6-sol medium)보다 **허용폭 δ 이상 낮지 않다.** δ는 파일럿 뒤 "허용할 수 있는 절대 오류 증가"와 "판정별 최대 손실"로 정한다(임의의 0.10을 쓰지 않는다).
- **H2 최소 성능:** 위험 판정의 재현율 하한(신뢰구간 하한)이 사전에 정한 값 이상이다.

## 7. 분석 계획

- **쌍체 비교:** 모든 설정이 같은 항목을 본다. 두 설정의 정오 차이는 **McNemar**, 비열등성은 **항목 단위 쌍체 부트스트랩**으로 차이의 신뢰구간을 구해 하한을 −δ와 비교한다. McNemar는 κ의 비열등성 검정이 아니므로 그 용도로 쓰지 않는다.
- **반복:** 반복 실행은 표본 수를 늘리지 않는다. 항목별로 묶어(클러스터) 분석한다.
- **다중 비교:** 가설별 검정에 Holm 보정.
- **비율의 구간:** Wilson 구간.
- **보고:** 실패·무효 응답을 포함한 모든 실행을 보고하고, 제외 기준은 사전에 정한다.

## 8. 표본 수

파일럿에서 **설정 간 불일치율**을 재서 McNemar 검정력 계산으로 정한다. 작은 효과와 드문 판정까지 판단하려면 **수백 항목 이상**이 필요할 수 있다. 그만큼 확보하지 못하면 결론을 "탐색적"으로 낮춘다.

## 9. 타당성 위협

| 위협 | 대응 |
|---|---|
| 판정자 1명 | 일정 기간 뒤 일부를 블라인드로 다시 판정(판정자 내 일관성). 판정자 간 차이는 독립된 두 번째 판정자가 있어야 잰다 |
| 우리 코드·코퍼스 편향 | 출처별 분포 보고, 공개 코퍼스 비중 확보 |
| 프롬프트 민감도 | 프롬프트는 별도 실험에서 요인으로 다룸 |
| 실험 중 모델 업데이트 | 응답의 모델 식별자·날짜 기록, 기간을 짧게 |
| 캐시 효과 | 순서 섞기, 캐시 칸 분리 |
| 조정자 누출 | 3절 조정자 분리 |
| 강도 수준이 모델마다 다름 | 완전 요인 설계가 아님을 인정하고, 강도는 모델 안에서만 비교 |

## 11. 결정 필요

1. **실험 수단:** 제품의 사전 판정이 API를 부를지 CLI를 부를지. API면 API 키와 그 과금이 필요하다.
2. **두 번째 판정자:** 가능한가. 없으면 파일럿과 본시험 모두 "판정자 1명" 한계를 달고 간다.
3. **판정 지침(0단계):** 판정 다섯 가지의 정의와 예를 먼저 쓴다.

## 파일럿 (1단계) 설계

- 판정 지침을 쓴 뒤, 층화한 소규모 표본(예: 30–40개, 드문 판정 포함).
- 설정: gpt-6-luna low, claude-haiku-4-5, gpt-6-sol medium. **프롬프트 하나, 반복 하나.**
- 보고: 판정별 혼동, 무효 JSON, 비용·지연, 판정자 이견(있으면), **설정 간 불일치율**.
- 결론: 본시험의 표본 수·δ·위험 판정 하한을 정한다. 어느 설정이 최고라고 말하지 않는다.
