# 작성 흐름 설계 — 새로 쓸 때와 수정할 때

상태: Codex 교차 검증 반영 (M1.8 S3.5–S3.6) · 날짜: 2026-09-30 · 검토 기록: `docs/reviews/2026-09-30-codex-authoring-flow-review.md`

## 1. 큰 축: NEW와 MODIFY

에이전트가 코드를 쓰는 상황은 둘로 나뉜다. 두 경우는 위험이 반대 방향이라 규칙을 따로 둔다.

| | NEW (새로 쓸 때) | MODIFY (있는 코드를 고칠 때) |
|---|---|---|
| 목표 | 처음부터 문형·약속대로 쓰게 한다 | 고친 부분만 약속에 맞추고, 나머지는 건드리지 않는다 |
| 가장 큰 위험 | 약속을 모른 채 쓰는 것 | 건드리지 않은 코드를 바꿔 diff·리뷰·git blame을 오염시키는 것 |
| 엄격함 | 높음: 알람은 모두 이번 작성자의 책임 | 낮음: 기존 알람과 새 알람을 구분한다 |

**판별은 경로나 diff 모양이 아니라 변경 전 기준본으로 한다.**
- 편집 전에 **기준본**(편집 직전 파일 내용)을 기록한다. 파일이 없었으면 기준본은 빈 파일이다.
- 결과의 표마다, 기준본에 **같은 자리의 같은 문형 표**가 있었는지 본다. 없었으면 NEW, 있었으면 MODIFY.
- 그래서 이름 변경·삭제 후 재생성은 기준본과 비교해 판정하고, 기존 표에 행을 보탠 추가 구간은 MODIFY다.

생성된 코드, 벤더 코드, 포매터가 소유한 파일, 테스트는 상위 축이 아니라 **적용 대상과 소유권 정책**이다. 설정의 `scopes`로 정한다(예: `vendor/**`는 끔, `test/**`는 장르 `TEST`).

## 2. 흐름

```
[쓰기 전]  기준본 기록 + GUIDE 주입
   NEW    : 핵심 3줄 + 이 경로의 장르 + 이 언어의 약속·예문 요약
   MODIFY : 핵심 3줄 + 편집할 영역에 있는 표의 문형·약속만 (짧게)
      ▼
에이전트가 쓴다
      ▼
[쓴 뒤]  리포트를 기준본과 비교
   · 안전 검사 실패  → 작업 실패로 알린다 (알람과 구분)
   · 새로 생긴 알람  → 에이전트에게 전달, 에이전트가 단순화·수정
   · 기존 알람       → 따로 표시만 (이번 작성자의 책임이 아님)
      ▼
판정이 필요한 알람 → review-queue (근거·기준본·제안 diff 포함, 중복 묶음) → 사람 승인 → 약속·예문 DB
```

## 3. MODIFY의 규칙

1. **표 단위 판단:** 편집한 줄과 겹치는 표만 본다. 편집 전에 그 표가 **이미 정렬돼 있었으면**(기준본에서 PASS) 편집 후 다시 정렬 대상이 된다. 원래 정렬돼 있지 않았으면 알람만 준다. 파일 전체를 레거시로 판정하는 비율 규칙은 쓰지 않는다(임계값이 자의적이고 작은 편집까지 막는다).
2. **새 알람만 책임:** 기준본과 결과의 알람을 **종류와 대상(문형, 표의 위치)으로 짝지어** 새로 생긴 알람만 에이전트에게 준다. 알람 총개수로 비교하지 않는다(하나가 사라지고 하나가 생기면 통과해 버린다).
3. **범위 재계산:** 편집이나 포매터가 줄을 옮기면 표 경계가 바뀐다. 범위는 결과 파일에서 다시 계산한다.
4. **동작 변경 없음:** 훅은 에이전트가 요청한 편집의 의미를 바꾸지 않는다.

## 4. 훅 실행 계약

자동으로 파일을 쓰기 전에 실제 호스트에서 아래를 확인하고 정한다. **확인하지 못한 호스트에서는 자동 정렬을 켜지 않는다.**

- 포매터 다음에 xxx가 도는 순서가 보장되는가(헌장 불변식 11).
- 훅이 바꾼 파일의 최종 내용과 diff를 에이전트에게 어떻게 돌려주는가(에이전트의 파일 기억이 낡지 않게).
- 여러 파일 편집: 파일별 기준본, 파일별 실패 처리, 부분 성공 표시.
- 재시도 때 중복 실행 방지.
- 지연: TypeScript는 파일당 약 0.3초. 연속 편집과 여러 파일에서 누적 지연을 잰다.

공통 규칙:
- 훅은 호스트 어댑터 층이다(Agent Skills 표준에는 훅이 없다). 모든 훅은 같은 CLI를 부르기만 한다.
- 사용자가 끌 수 있다: 전부 끄기 / 리포트만 / 정렬까지.

## 5. AI 경계

- 에이전트는 알람을 받고, 판정 제안을 review-queue에 쓸 수 있다.
- 에이전트는 **약속·예문 DB에 쓰는 승인 경로를 부를 수 없다.** 승인 명령은 사람만 실행한다(헌장 불변식 8).
- 대기열 항목은 근거, 기준본, 제안 diff를 담고, 같은 대상의 중복 제안은 하나로 묶는다.
