# 코드는 언어다 — 사람 승인 기반 코드 정렬을 위한 LLM 사전 판정: 성능 제약하 저비용 설정 선택의 사전 등록 연구

2026-10-01 · 공동 작성: 사람 저자, Claude(Anthropic), Codex Astra(OpenAI) — 기여는 끝의 "저자 기여" 참조

## 초록

프로젝트의 코드 정렬 약속을 유지하려면 정렬을 **기계적으로 적용하는 일**과 패턴이 **적합한지 판단하는 일**을 구분해야 한다. 본 연구는 사람이 승인한 패턴 데이터베이스와 공백 편집에 대한 보존 검사를 사용하는 결정적 정렬기를 연구 맥락으로 삼고, 아직 승인되지 않은 패턴 후보를 분류하는 LLM 설정의 성능과 호출 비용을 평가하는 사전 등록 실험을 제안한다. LLM의 출력은 사람의 판정을 보조하며 승인을 대신하지 않는다.

탐색 단계에서 TypeScript·Python 공개 저장소 8개로부터 현재 탐지기가 표 8,093개를 추출했고, 깊이를 제외한 조회 키 72개 중 빈도 상위 20개가 표 발생 건수의 96%를 차지했다. 이는 해당 코퍼스와 탐지기에 한정된 기술 통계이다.

본시험에서는 탐색 자료와 분리된 패턴 후보를 고정된 지침에 따라 복수의 사람이 독립적으로 판정하고, 사전에 지정한 모델 설정을 실행기가 강제하는 동일 입력 조건에서 비교한다. 적격 조건은 기준 설정 대비 정확도 비열등성, 절대 정확도 하한, 위험 범주별 재현율 하한이며, 적격 설정 가운데 실패·재시도를 포함한 후보당 기대 호출 비용이 가장 낮은 설정을 고른다. 결론은 지정한 후보와 평가 분포에서의 모델 선택에 한정하며, 정렬의 가독성 개선이나 일반적 의미 보존을 검증하지 않는다.

## 1. 서론 — 두 가지 비대칭

같은 코드가 **어느 도구가 마지막에 도느냐**에 따라 모양이 달라진다. 수직 정렬을 넣은 코드는 포매터를 거친 뒤 정렬이 지워지거나, 역할이 아니라 문법 종류로만 다시 묶인다. 모양에 대한 판단이 코드의 성질이 아니라 도구 실행 순서에 따라 달라지는 것이다. 이것이 첫 번째 비대칭이다.

두 번째 비대칭은 **쓰는 쪽과 보는 쪽의 기준**이다. 프로젝트의 형식 약속이 제공되지 않거나 일관되게 적용되지 않으면, 코딩 에이전트의 출력은 약속에서 벗어날 수 있다. 이를 LLM으로 검토하면 검토자는 호출마다 비용을 내고, 약속을 모르는 검토자는 약속 대신 일반적 취향으로 판단할 수 있다(6절의 탐색 관찰 참조).

우리는 두 비대칭을 다음 방식으로 다룬다. 모양의 **적용**은 결정적 엔진이 승인된 약속에 따라 공백만 바꿔 수행하고, 새 패턴이 **약속이 될지**는 사람이 판정한다. LLM은 사람의 판정 대기열 앞에서 후보를 미리 분류하는 데만 쓴다.

이 원고의 **확인적 주장은 하나**다. 미승인 패턴 후보의 사전 판정에서, 지정한 후보 설정 중 적격 조건을 만족하며 추정 비용이 가장 낮은 설정을 고른다. 정렬기, 문형 체계, 패턴 DB는 이 과제를 구성하는 **연구 맥락**이며, 그 유용성이나 가독성 효과는 이 연구에서 검증하지 않는다.

## 2. 공준

아래는 **가정**이다. 이 연구는 이를 증명하지 않고, 이것에서 출발한다.

- **공준 1 (역할).** 같은 역할을 하는 코드 요소를 수직으로 맞추면 비교를 도울 수 있다. 역할은 언어 기호(`=`, `:`, `from` 등)가 표시하며, 기호는 문장 안에서 조사처럼 역할을 드러낸다.
- **공준 2 (보존 계약).** 자동 편집은 정의된 보존 조건(토큰·문자열·주석 동일, 공식 파서 재파싱 진단 동일, 멱등)을 통과할 때만 적용하고, 통과하지 못하면 원본을 둔다.
- **공준 3 (승인).** 무엇이 약속인지는 사람만 승인한다. 빈도나 모델 판단만으로 약속이 되지 않는다.
- **공준 4 (결정성).** 약속의 조회는 정확 키 일치로만 하며, 유사도 검색을 쓰지 않는다.

"코드는 언어다"는 공준 1을 표현하는 **비유**이다. 코드 이해는 주로 언어 영역이 아니라 영역 일반적 실행 기능 영역에 의존한다는 보고(Ivanova et al., 2020)가 있으므로, 분류는 비유가 아니라 파서가 먼저 한다.

## 3. 조작적 정의

아인슈타인(1905)이 시계를 맞추는 **절차**로 동시성을 정의했듯, 여기서는 개념을 측정 절차로 정의한다.

| 개념 | 절차에 의한 정의 |
|---|---|
| **표** | 한 문단(빈 줄로 나뉜 묶음) 안에서 같은 문형의 문장이 3행 이상 이어진 것. 탐지기가 손실 없이 나눌 수 있어야 한다 |
| **문형** | 지원 대상 구문을 분류하는 작업용 범주 9개: 가져옴, 정의, 기술, 대응, 나열, 동작, 변경, 조건, 끝냄. 코드 전반의 완전한 분류라고 주장하지 않는다 |
| **조회 키** | `v1\|언어\|컨테이너\|kind\|정규화한 축 순서`. 들여쓰기 깊이는 넣지 않는다 |
| **패턴 후보 (판정 단위)** | 승인되지 않은 조회 키 하나와, 고정된 선정 절차로 뽑은 대표 예문 묶음(원문·정렬 결과) |
| **판정 라벨** | 판정 지침(부록 B)의 필요조건·배제조건을 따르는 범주. `unsure`는 정답 범주가 아니라 **판단 유보**로 다룬다 |
| **위험 범주** | 놓치면 사람의 재검토 부담이나 잘못된 약속 승인으로 이어지는 범주(`different-role`, `missing-kind`). 위험은 코드 손상이 아니라 업무상 손실로 정의한다 |
| **배포 분포** | 운영에서 사람 대기열로 **새로 들어오는 미승인 후보**의 분포. 코퍼스의 표 발생 빈도와 구분한다 |

## 4. 귀결

공준과 정의에서 다음이 따른다. 각 명제에 근거의 종류를 표시한다.

**명제 1 (결정성) — [구성에 의한 증명]**
같은 입력 파일, 같은 엔진 버전, 같은 패턴 DB에서 리포트는 같다.
*증명.* 탐지·정렬·알람은 입력과 설정만의 함수로 구현되고 외부 상태를 읽지 않는다. 조회는 공준 4에 따라 키 일치와, 범위의 구체성과 레코드 id로 정해지는 순서에 의해서만 결정된다. 같은 층·같은 구체성에서 상태가 다르면 파일 순서로 정하지 않고 "충돌"로 보고한다. 따라서 출력은 입력의 함수다. ∎ (구현이 이 명세를 지키는지는 테스트로 확인한다.)

**명제 2 (보존 계약) — [검사로 확인, 형식적 의미 보존의 증명 아님]**
적용된 모든 편집은 토큰 스트림 동일, 재파싱 진단 동일, 멱등을 만족한다.
*근거.* 공준 2에 따라 이 조건을 통과하지 못한 편집은 적용되지 않는다. 이는 검사 통과에 대한 진술이며, 프로그램 의미 보존의 형식적 증명이 아니다. Python처럼 들여쓰기가 의미를 갖는 언어에서는 줄 앞 공백을 편집 대상에서 제외한다.

**명제 3 (새 알람의 식별) — [반례와 구성]**
알람 **총개수**를 비교하는 규칙은 새 알람을 놓칠 수 있고, (종류, 대상) 다중집합 짝짓기는 이를 막는다.
*증명.* 반례: 편집 전 알람 {a}, 편집 후 {b}(a ≠ b)이면 개수는 1로 같아 총개수 규칙은 새 알람 b를 놓친다. 구성: 알람의 대상을 첫 줄 내용(공백을 접음)으로 정하고 (종류, 대상) 다중집합으로 짝지으면, b는 짝이 없어 새 알람으로, a는 사라진 알람으로 분류된다. ∎

**명제 4 (예측의 상한) — [가정에서의 추론]**
판정이 (후보, 적용할 약속)의 함수라면, 같은 규범 정보를 받은 모델의 사람 판정 일치도는 **판정자 간 일치도**를 넘어 해석될 수 없다.
*추론.* 정답 자체가 판정자 간 불일치만큼 흔들리므로, 그 이상의 일치는 특정 판정자의 취향을 모사한 것과 구별되지 않는다. 따라서 본시험은 복수 판정자를 설계에 포함해야 하고(7절), 모델에는 사람과 같은 약속 정보를 준다.

## 5. 관련 연구

- **코드의 자연성과 관례.** 코드는 자연어보다 반복적이고 예측 가능하며(Hindle et al., 2012), 그 이유 중 하나는 익숙한 형태의 선택이다(Casalnuovo et al., 2019). 코드베이스에서 관례를 학습해 제안하는 연구가 있다(Allamanis et al., 2014). 이 연구들은 우리 설계의 **동기**이지만, 제안한 문형 체계의 타당성을 직접 검증하지는 않는다. 우리는 학습된 관례를 자동 적용하지 않고 사람 승인을 거친다.
- **가독성 측정.** 가독성 평정을 학습한 지표(Buse & Weimer, 2010)가 있으나, 시각적 선호와 실제 이해 성능은 구분해야 한다. 이 연구는 가독성 효과를 측정하지 않는다.
- **읽기의 지식 구조와 오해 패턴.** 숙련자는 프로그래밍 플랜과 담화 규칙으로 코드를 읽고(Soloway & Ehrlich, 1984), 작은 코드 패턴이 오해율을 높이며(Gopstein et al., 2017), 이름과 동작의 불일치는 품질 저하로 인식된다(Arnaoudova et al., 2016). 메서드를 의미 블록으로 나누는 자동화도 연구되었다(Wang et al., 2011).
- **판단 유보와 사람 참여.** 확신이 낮을 때 판단을 유보하는 선택적 분류(Geifman & El-Yaniv, 2017)는 `unsure`와 사람에게 넘기는 비율을 다루는 틀이다.
- **LLM 평가자.** LLM을 평가자로 쓸 때의 편향과 한계가 보고되었다(Zheng et al., 2023). 다만 이 과제는 일반 답변 품질 평가가 아니라 **규범에 따른 코드 패턴 분류**에 가깝다.
- **조사할 영역.** 공백·들여쓰기·정렬의 실험적 효과, 구조적 pretty-printing과 구체 구문 보존 변환, 주관적 라벨의 판정자 불일치, 소프트웨어공학 벤치마크의 누출과 저장소 간 일반화, 비열등성 설계.

## 7. 확인적 연구 설계

### 7.1 연구 질문과 적격 조건

**RQ.** 지정한 후보 설정·호출 조건·가격 기준에서, 미승인 패턴 후보의 사전 판정에 적격인 설정 중 추정 비용이 가장 낮은 것은 무엇인가?

후보 m의 정확도를 A_m, 기준 설정의 정확도를 A_b, 위험 범주 c의 재현율을 R_{m,c}라 하고, L을 등록한 방법으로 계산한 단측 신뢰하한이라 할 때, 설정 m은 다음을 **모두** 만족할 때 적격이다.

    L(A_m − A_b) > −δ,    L(A_m) ≥ a_min,    L(R_{m,c}) ≥ r_min,c  (각 위험 범주 c)

δ, a_min, r_min,c의 수치는 파일럿 전에 **허용 가능한 추가 오분류와 사람의 재검토 부담**을 근거로 정하며, 경량 모델의 관측 성능에 맞춰 정하지 않는다. 기준 설정도 적격성을 자동으로 보장받지 않는다. 모든 설정이 부적격이면 결론은 "적격 설정을 확인하지 못했다"이다.

### 7.2 후보 설정

gpt-6-luna(low, medium), claude-haiku-4-5, 기준 gpt-6-sol(medium). 강도 수준이 모델마다 다르므로 완전 요인 설계가 아니며, 강도는 모델 안에서만 비교한다. 프롬프트 효과(약속·예문 유무)와 자동 올리기 사다리는 별도로 등록한다.

### 7.3 실험 수단과 동일 조건

결론은 수단에 묶인다. API 직접 호출이면 모델 설정에 대한 결론이고, CLI(`codex exec`, `claude -p`)면 그 CLI·버전·설정 조합에 대한 결론이다. 동일 조건은 문서가 아니라 **실행기가 매니페스트로 강제**하고, 어긋나면 실행을 거부한다(부록 C). 공급자 쪽 무작위성, CLI의 숨은 시스템 지시, 실험 중 모델 업데이트는 고정할 수 없음을 보고하고, 응답의 모델 식별자와 기간을 기록한다. 실험을 띄우는 세션은 채점하지 않는다.

### 7.4 표본과 분할

- **단위:** 패턴 후보(3절). 같은 유형의 표 수천 개가 독립 판정 수천 개가 되지 않는다.
- **새 자료:** 탐색 자료(6절)에 접근하지 않은 새 저장소 또는 새 커밋 구간에서 후보를 만든다. "새 유형 일반화"와 "새 저장소 일반화"는 서로 다른 평가로 정의한다.
- **표집:** 위험 범주 후보를 과표집하되 주 정확도는 배포 분포 추정이 없으면 **후보 단위 정확도**를 쓰고, 표 빈도 가중 정확도는 보조로 둔다.
- **제외:** 모델 출력을 보기 전에 정한 규칙(생성 코드·벤더 코드·중복)으로만 제외하고, 제외 수와 사유를 공개한다.

### 7.5 정답

최소 두 명이 모델 출력 없이 판정 지침에 따라 **독립** 판정하고, 합의 전 라벨·이견 이유·조정 결과를 보존한다. 설계에 참여하지 않은 판정자를 포함한다. 합의되지 않은 후보의 처리는 미리 정한다. 판정자 내 일관성은 일정 기간 뒤 일부를 블라인드로 다시 판정해 잰다.

### 7.6 파일럿

지침의 적용 가능성, 출력 스키마, 판정자 이견, 설정 간 불일치율, 범주 비율, 분산을 추정한다. 파일럿 후보는 본시험에서 제외한다. 파일럿의 결론은 "본시험 설계가 실행 가능한가"이며, 어느 설정이 최고라고 말하지 않는다.

## 8. 분석 계획

- **주 지표:** 후보 단위 정확도와 위험 범주별 재현율. 모델의 `unsure`와 무효 출력은 **비정답**으로 계산하고, 응답률과 응답한 후보에서의 정확도를 따로 보고한다. 위험 후보에서 `unsure`가 나오면 위험 범주를 식별한 것으로 세지 않는다.
- **보조:** 균형 정확도, macro-F1, 혼동표, 표 빈도 가중 정확도. Cohen κ와 Gwet AC1은 **모델과 조정된 정답 사이의 일치도**로 명시해 보고한다(순서 없는 범주이므로 가중 κ는 쓰지 않는다).
- **신뢰하한:** 단측 유의수준 0.025. 후보와 저장소의 의존 구조를 보존하는 군집 부트스트랩을 쓴다. Wilson 구간은 독립적이고 가중하지 않은 이항 관측에만 쓴다. 반복 실행은 항목별로 묶는다.
- **검정력:** 7.1의 공동 적격 조건을 반영한 **시뮬레이션**으로 90% 검정력에 필요한 후보 수와 위험 범주별 정답 양성 수를 정한다. McNemar 차이 검정의 검정력으로 정하지 않는다.
- **다중성:** 확인적 후보와 가설 집합을 열거하고 Holm 보정을 적용한다. 한 후보가 여러 조건을 모두 통과하는 문제와 여러 후보 중 하나를 고르는 문제를 구분한다.
- **중단 규칙:** 항목 수와 반복 횟수를 고정하고, 중간 성능을 보고 표본을 늘리거나 멈추지 않는다. 예산·기간 상한에 걸리면 미완료로 보고한다.
- **실패 규칙:** 시간 초과, 공급자 오류, 스키마 오류, 응답 거부, 문맥 한도 초과의 재시도 횟수와 채점을 미리 정한다. 모델 버전이 바뀌면 실행을 멈추고 변경과 재개 규칙을 기록한다.
- **비용:** 고정한 가격 기준일의 공급자 공식 가격(USD/100만 토큰)으로 입력·캐시 읽기·캐시 쓰기·출력을 환산한다. 주 비용은 **시도한 후보 한 건당 총 호출 비용**(실패·재시도 포함)이며, 완료 후보당 비용은 함께 보고한다. 캐시 사용 조건과 워밍업 비용 처리는 미리 정한다. 적격 설정이 여럿이면 비용 차이의 불확실성과 함께 보고한다.
- **모든 실행을 보고한다.**

## 10. 재현성과 윤리

코퍼스는 허용 라이선스 공개 저장소를 커밋 SHA와 파일 선택 규칙으로 고정하며 원본은 저장소에 넣지 않는다. 외부 LLM에는 공개 소스만 보낸다. 판정 지침, 전체 프롬프트, 매니페스트, 원시 응답, 사람 판정 기록, 분석 코드를 공개한다.

## 구성에 관한 주

이 원고는 Einstein(1905)의 구성 — 현상의 비대칭에서 출발해 추측을 **공준**으로 올리고, 개념을 측정 **절차로 정의**한 뒤, 공준에서 **귀결을 연역**하고 관측 가능한 결과를 제시하는 흐름 — 을 따르고, 여기에 현대 경험 연구의 요소(관련 연구, 사전 등록한 가설과 통계 분석, 타당성 위협, 재현성)를 결합했다. 명제마다 근거의 종류([증명], [검사로 확인], [가정에서의 추론])를 표시한 것은 연역적 주장과 경험적 주장을 섞지 않기 위해서다. Registered Report 형식은 Chambers(2013)를 따른다.
