# First-use formatting fix — 2026-10-21

[Issue #1](https://github.com/Woo-JongHo/rowgrid/issues/1) reported a successful Windows plugin installation followed by
format refusals for every eligible Python file: no external formatter was configured and the bundled approval preset was empty.
The user authorized implementation, approved the two concrete rule candidates, and separately approved CC0-1.0 for the
four newly authored synthetic examples only. Woo-JongHo made both decisions in this session on 2026-10-21. Public
approval records use `maintainer` under the existing privacy contract. Repository/product licensing is still undecided.

## Resulting behavior

- Standalone BoxBox alignment is the default; a configured formatter remains a mandatory preceding stage for that language.
- The bundled preset contains two conventions, four examples and two decisions with complete approval proofs. TypeScript
  allows top-level single-call `const`/`let`/`var` declaration tables of 2+ rows in `.ts`; Python allows 3+ consecutive simple
  name assignments at one indentation. Minimum-row exclusions remain read-only.
- Resource declarations, awaited/constructor initializers and dotted Python targets have distinct keys, so the narrower
  approval cannot silently extend to them. Unknown, candidate, rejected, conflicting or stale proof still prevents writes.
- Parsing, BoxBox content preservation, two complete cycles to a byte fixed point, provenance rechecks and one atomic
  replacement still apply. Dry-run exercises the same pipeline and preserves the original.
- Check distinguishes alignment findings from provisional approval eligibility (`verification=not-run`). The format result
  reports `formatMode`, the actual `formatterExecuted`, and `formatter=null` in standalone mode.
- Windows formatter execution resolves native/Node commands safely, bounds output, and waits for process-tree cleanup on
  timeout. Arbitrary batch files receive configuration guidance. Configured failures never silently select standalone mode.
- An actual Windows npx test exposed an unrelated `codex.exe` shadowing OpenAI Codex. Native candidates now require a
  bounded `codex-cli <version>` identity response before selection; the installer continues to the valid PATH candidate.
