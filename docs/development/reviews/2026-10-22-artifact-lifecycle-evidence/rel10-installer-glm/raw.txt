# REL10 installer phase & Claude registration — final read-only audit

Scope honored: static review of the eight frozen files only; no execution, no approval, no native-acceptance claim. `platform.mjs`, `launcher.mjs` and HUD sources are outside the frozen set; their contracts are pinned only by the shown tests.

## Mandatory questions

**1. Partial-state cleanup boundary — no defect.** `entry.mjs installHost` finally block rolls back only when `prepared`: `!launched`, or `!signaled && exitStatus !== 0 && state.read()?.phase === "prepared"` (read wrapped in try/catch → false on error). `install.mjs` issues no host-mutating verb before `state.advance("host-registration-started")` — only `--version`, `plugin install --help`, list JSON, `plugin update --help`, `npm install` into the destination-local runtime — so phase `prepared` provably precedes host mutation. Signals → retain (SIGTERM case). Exit 0 without `verified` → throw → retain (`process.exit(0)` case). Missing/corrupt receipt after launch → retain (`unlinkSync`, broken-JSON cases). Retries re-read a valid identity-bound receipt (schema/realpath root/name/version/host/marketplace; symlink refused via lstat), remove it, create a fresh `wx` receipt; foreign and symlink receipts throw before backup creation, byte-proven unchanged. Backups: `mkdtemp` sibling; copy failure self-cleans or reports the retained partial backup (`backup`, `backup-cleanup` faults); restore/remove failures retain the backup with its exact path in the error (`restore`, `remove`); only the run's own backup is deleted, and only after verified success or proven pre-mutation restore (`cleanup` fault warns and retains). Restored backups recontain the prior receipt, preserving recovery markers.

**2. Pre-copy shared guard — no defect.** `assertClaudeCatalog(destination, metadata, true)` runs before backup/copy for claude when the destination exists. lstat rejects symlinks/wrong types for `.claude-plugin` and `marketplace.json`; parse rejects malformed; the catalog must be exactly our marketplace name with the single `boxbox` → `./plugin` plugin. The artifact test proves byte-identical catalog, byte-identical fake-host state file, byte-identical host call log (zero host commands) and zero `.boxbox-repair-` dirs for shared/malformed/symlink catalogs. Only ENOENT is permitted.

**3. Foreign/phase protection — no defect.** Receipt identity is exact and symlink-refused. Child ordering: capability preflight (`--scope` regex on `plugin update --help`), `marketplace(false)`/`plugin(false)` ownership — exactly one directory-source marketplace, `realpath(installLocation) === realpath(path)`, same parent directory, bundle+manifest identity, `source === realpath(resolve(dirname(intended), bundle.version))`, strict catalog re-check, shared-id and duplicate/ambiguous-scope refusal — all before the phase transition and any mutating verb (registration test asserts calls ⊆ {`--help`, `list`}). `advance` permits only prepared→started→verified, atomically.

**4. Scoped update identity — no defect.** `verify()`: exact-root marketplace check; exactly one enabled user-scope `boxbox@boxbox-plugins`; when stale, exactly one `["plugin","update",id,"--scope","user"]`, then re-list of marketplace and plugin; still stale → throw. Cached manifest name/version plus `runtime.cli`/`runtime.node` realpath equality against the intended `plugin/runtime.json` — precisely the gate the measured 0.2.3-cache defect requires. Tests pin the single-update array, no second update on re-verify, and the "wrong plugin version"/"runtime" failures; a zero-exit update that changes nothing fails the child, which (post-`started`) forces parent retention.

**5. Meaningful failures and preservation — no defect.** The retain message names destination, receipt and backup and prescribes inspection/retry/exact-registration removal; no rollback is claimed. README wording matches the implementation (retention semantics, retry rules, foreign receipts, "partial-state retention, not an automatic rollback", pending native Windows verification). Overlay copy preserves extra user bytes (`preserved.txt` survives failed-then-successful rerun; plugin files byte-equal across a failed registration).

**6. Pack allowlist — no defect.** Builder copies entry→`bin/`, the three helpers→`payload/` and each host root, launcher→`plugin/scripts/boxbox.mjs`, `product/hud`→`plugin/scripts/hud`, marketplace JSON, engine tarball, `bundle.json`. The artifact test asserts exact equality of the packed file list with the expected allowlist, byte-equality of references and the nested engine tarball, no ROOT leakage, `bun` absent on PATH during the npx run, and executes doctor/check/format/all three hooks/`--version` from the packed artifact — an omitted install-time or basic-runtime dependency cannot pass silently.

**7. Tests — adequate; no missing executable regression that permits a concrete safety defect.** Negative paths are proven at byte/log level: host call-log byte equality (catalog guard, `--scope` preflight), fake-host state-file equality, plugin-file equality across failed registration, on-disk receipt phase, backup contents, preserved user bytes, and exit-code propagation (19/42/31). The parent/child simulations run the real `entry.mjs` under node with isolated data roots. The unexercised surfaces — real `claude plugin update` cache behavior, native Windows entry execution — are exactly the acknowledged pending native cells, not static gaps.

## Optional observations (non-blocking)

1. `entry.mjs` finally, success branch: `state.remove()` is unprotected; a unlink failure after a verified install exits 1 with a raw error and the retained backup is neither removed nor reported. Smallest correction: try/catch with the retained-path warning, or reorder backup cleanup before receipt removal. Filesystem-fault only; conservative in effect.
2. `marketplace(false)` surfaces raw ENOENT when a listed host path no longer exists instead of an ownership message — safe but cryptic.
3. The versioned destination directory itself may be a symlink (receipt and catalog symlinks are refused); writes follow it. Installer-owned namespace; informational.
4. The retain message prints `Receipt: ${state?.path}` even when the child deleted the receipt; wording could note it may be absent.
5. `build-installer-artifact` replaces the SKILL sentence by regex without asserting a match; the e2e forbidden-string check ("standard shim requires") backstops it today, but an explicit match-count assertion would pin drift directly.
