## 2. Boundary-by-boundary review (no mandatory findings)

1. **Runtime records** (`runtime-record-validation.ts`): rejects null, arrays, primitives; non-empty strings unless `empty` opt-in (candidate `approvedBy`); duplicate string-array values; empty keys/non-finite numbers. Fail-closed and consistent with invariant 1.
2. **Layout policy** (`layout-policy.ts` + `typescript-layout.json`): `IMPLEMENTED_LAYOUT_KINDS` (18) exactly equals the JSON `kinds` keys; `exactKeys` rejects missing/unknown at root, `rowKinds` (declaration only), per-kind, and `minRows`. Duplicate axes, gap∩insert overlap, bad schemaVersion/language/operation, and `minRows.value < 2` all throw. Axis identifiers match the JSON (incl. `{i}` forms); every axis resolves in `AXIS_NOTES` after `{i}` stripping (checked at load, `grid-kinds.ts:805`). `minimumRowsOf` preserves the every-row-has-`equals` ⇒ 2 floor. Kind gap values hard-coded in `grid-kinds.ts` do not contradict the JSON (which deliberately omits per-kind gaps); column/edit behavior stays in detectors/`RowBoundary`. No widened keys or approval authority added.
3. **Pattern catalog**: validator enforces 9 families, all five case kinds per family, `verification === "design-only"`, duplicate family/case rejection. `readPatternCatalog` rejects absolute/`..`/backslash evidence paths, any symlinked component, non-files, and physical escapes via `realpath`. SQLite index: ownership marker check before replacement, temp-file + integrity/foreign-key checks + atomic rename; runtime rule selection imports none of it. Consistent with invariant 3 (45 = 9×5 design-only cases; projection matches).
4. **Public Check**: `validateSyntax` yields distinct `valid`/`invalid`/`error`, UTF-8 round-trip checked, per-language real parser (TS server, python3, JSON.parse/yaml 1.2-core strict). `FileResult.parse` remains `not-run` in Check. `formatReadiness` evaluates detected groups through `evaluateApproval` and never marks approval eligible without verified proof; JSON/YAML groups produce no new public approvals or license decisions.
5. **Structured writes**: strict 1.2-core YAML; non-1.2 `%YAML` rejected; unresolved aliases error; anchors/tags/block scalars/flow/complex keys/multi-pair lines refused with reasons; runs require ≥3 adjacent, same-parent, same-indent single-line scalar rows; `preservesStructured` enforces line-count, indent, trailing-whitespace, whitespace-insensitive content, and row-skeleton equality; `analyzeStructured` throws on preservation escape; pipeline requires approval on every candidate group, REFUSE-free result, two-cycle byte fixed point, provenance stability before and at commit, atomic replacement. I traced the YAML original/candidate scenario statically only, as required.
6. **Alias/install**: `check-layout.ts` validates `@/` aliases lexically and physically (symlink components rejected, single whitelisted relative exception); Windows separators normalized before containment checks; `load-source-file.ts` rejects `..`/`../` after backslash normalization and physical escapes. `install.sh` ownership model (marker identity, hash for files, readlink equality for symlinks) refuses stale markers, edited copies, and foreign symlinks; uninstall removes only owned entries. Isolation is demonstrated only by the recorded isolated checks — I do not infer every platform ran natively.
7. **Hooks**: `snapshotExclusions` excludes only the receipt namespace; hook errors are caught and never trap the host; `hooks.json` matches the three events; stop-block-once marker logic is self-consistent. Plugin data records stay out of the project when host data is provided.
8. **HUD**: `record.mjs` never asserts host acceptance; `status.mjs` bounds sizes, refuses symlinks/oversized/future/malformed receipts, keeps `hostAcceptance: "unverified"`, `file not run`, session filtering by full session hash (cannot borrow project history), stale ⇒ "historical"; setup refuses foreign/user-edited config and Windows; entry guards now compare canonical realpaths with safe-false on failure; tmux is driven via argv with trailing-`;` escaping.

## 3. Non-mandatory advisories (speculative hardening / evidence gaps)

- `codex.mjs` `tmuxArgument` escapes only **trailing** semicolons; behavior of embedded spaces/quotes/`;` inside `-c`/`--plugin-root` values relies on tmux's argv-joining semantics and is unverified on a native host. Ties directly to the still-pending native rerun.
- `status.mjs` `jsonFile`: where `O_NOFOLLOW` is undefined, the `regular()` lstat→open window is a residual TOCTOU (macOS/Linux define it; harden by fstat-mode check after open).
- `runtimeString` accepts control characters; consider rejecting them in record fields (display/hardening only).
- `install.sh` `dependency_names` requires `node` even for bun-only installs (fails closed with a possibly misleading message).
- `pattern-catalog.ts:143` uses the Bun global `crypto.randomUUID()` while importing `createHash` from `node:crypto`; fine under `bun:sqlite`, but an explicit import would be clearer.
- The failed archive `boxbox-plugin-0.2.4.tgz` (SHA-256 `13e099…0177`) still contains the broken entry guards; it must not be republished, and a rebuilt artifact with a new digest plus a native rerun remains outstanding. This is packaging follow-up explicitly acknowledged by the project, outside this audit's publication scope, and not a defect in the bound source.

## 4. Conclusion

Within the eight stated invariants and against the supplied bound snapshot, I found no correctness, safety, authority-boundary, portability, packaging, or materially false-documentation defect that must be fixed before READINESS1 closes. The snapshot's own honest limits (design-only catalog cases, pending JSON/YAML publication decisions, skipped Rust/Kotlin toolchain checks, and un-reverified native host acceptance after the entry-guard fix) are accurately stated and remain visible.

**Verdict: PASS** — conditional on the manifest hashes being current, and explicitly *not* a claim of native macOS host acceptance, a passed post-fix full suite, or JSON/YAML publication approval.
