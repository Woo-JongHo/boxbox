## What the original scenario does and does not establish

A GitHub plugin download is not equivalent to installing its local engine. The repository shim requires an explicitly configured local engine and refuses an unconfigured invocation; the npm installer candidate carries the private engine. The shipped Claude inspector is intentionally read-only, while source changes remain the main agent's explicitly authorized work. Codex can discover enabled hooks yet skip them until trust review; T6/T8 include that negative control.

The missing `Bash` matcher is a confirmed coverage defect, and zero-group/suggestion receipts needed clearer meanings. These measured conditions must not be collapsed into one certain “engine missing” diagnosis for the original session, whose exact installation and transcript were not recovered. The new namespace regressions in T7 arose during this hardening loop and were caught before publication. See the [installer contract](../../../product/installer/README.md) and [event acceptance contract](../agent-portability.md#current-distributable-plugin-boundary).

A further runtime boundary was confirmed in this loop: native read-only Python `check` failed while creating a parser temporary directory, even though the engine existed. `guide` then returned empty guidance. A4 feeds the same CPython parser through stdin; final v4 actually detects the group and returns approved guidance without TMPDIR or permission changes. This is a confirmed defect in that tested scenario, not a reconstruction of the original session's exclusive cause.
