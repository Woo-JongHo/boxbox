# 같은 프롬프트는 같은 조건이 아니다 — 교차 실행 환경에서 LLM 설정을 비교할 때의 조건 통제와 판단 기준

*방법론 원고 · 2026-10-01 · 사례: 코드 정렬 패턴의 사전 판정 (8절)*

---

## 초록

LLM 설정 A가 B보다 "이 작업에 더 좋다"는 주장은 흔히 같은 프롬프트를 두 모델에 보낸 결과로 뒷받침된다. 그러나 같은 프롬프트 바이트는 같은 조건을 보장하지 않는다. 에이전트 CLI의 숨은 시스템 지시, 사용자 전역 지시 파일, 프롬프트 캐시, 실행 순서와 시각, 공급자의 무작위성과 모델 업데이트가 결과에 끼어들고, 이 가운데 일부는 설정 차이와 교락된다. 이 원고는 조정 세션이 여러 공급자의 모델을 자식 프로세스로 부르는 **교차 실행 환경**에서, 좁은 분류 과제의 설정을 비교하기 위한 방법을 정리한다. (1) 변동의 원천을 통제 가능·부분 통제·통제 불가로 분류하고 각각의 처리(강제, 무작위화, 측정·보고)를 정한다. (2) 조건은 문서가 아니라 실행기의 매니페스트로 강제하고, 조작 점검·A/A 시험·기준 항목 재실행으로 통제가 실제로 작동했는지 확인한다. (3) 판단 기준은 결과 전에 고정하며, 절대 정확도·위험 범주 재현율·기준 대비 비열등성을 모두 통과한 설정만 비용으로 비교한다. 비용은 공급자별 과금 구조를 가격 정본으로 환산해 시도 건당 총비용으로 비교한다.

## 1. 서론 — 같은 프롬프트, 다른 조건

두 모델에 똑같은 글자를 보냈다. 그런데 한쪽은 CLI가 붙인 수천 자의 시스템 지시와 사용자의 전역 지시 파일을 함께 받았고, 다른 쪽은 그렇지 않았다. 한쪽은 캐시가 데워진 뒤에 돌았고, 다른 쪽은 차가운 캐시에서 돌았다. 결과가 다르다면, 그 차이는 모델의 차이인가?

이것이 이 원고가 다루는 **비대칭**이다. 비교하는 쪽은 입력을 같게 만들었다고 믿지만, 모델이 실제로 받은 조건은 같지 않다. 게다가 "모델 A가 더 낫다"는 결론에는 모델, 호출 수단, 프롬프트, 강도, 가격이 한데 섞여 있기 쉽다.

이 원고의 기여는 다음과 같다.

1. 교차 실행 환경에서 **변동의 원천**을 분류하고, 원천마다 처리 방식을 정한다(4절).
2. 조건을 **실행기가 강제·기록**하고, 통제가 실제로 작동했는지 **확인하는 절차**를 둔다(6절).
3. 결과 전에 고정하는 **판단 기준**과, 공급자 간 **비용 비교 규칙**을 정한다(7절).
4. 이를 코드 정렬 패턴의 사전 판정 과제에 적용한 설계를 보인다(8절).

## 2. 공준

- **공준 1 (한 번에 하나).** 두 설정의 비교는 하나의 변인만 달리할 때에만 그 변인의 효과로 해석한다. 여러 변인이 함께 바뀌면 결론은 그 조합에 대한 것이다.
- **공준 2 (강제와 기록).** 같게 해야 할 조건은 문서가 아니라 실행기가 강제하고, 실행마다 기록한다. 강제할 수 없으면 기록한다.
- **공준 3 (측정되지 않은 것은 통제된 것이 아니다).** 통제할 수 없는 변동은 무시하지 않고 반복·측정해 크기를 보고한다.
- **공준 4 (사전 고정).** 판단 기준, 허용폭, 표본 수, 제외 규칙은 결과를 보기 전에 정한다.
- **공준 5 (조정자와 채점자의 분리).** 실험을 띄우는 세션은 결과를 채점하지 않는다. 채점은 정답과 대조하는 결정적 코드가 한다.

공준 1과 3은 무작위 배정과 반복으로 교란을 다루는 실험 설계의 원칙(Fisher, 1935)을 LLM 호출에 옮긴 것이다.

| **비용** | 가격 정본(부록 B)으로 환산한, 시도한 항목 한 건당 총 호출 비용(실패·재시도 포함) |

## 4. 변동의 원천과 처리

| 원천 | 예 | 통제 수준 | 처리 |
|---|---|---|---|
| 입력 | 프롬프트 바이트, 예문 수, 코드 문맥 범위 | 통제 가능 | SHA-256으로 강제 |
| 작업 환경 | 작업 폴더의 파일, 이전 실행의 산출물 | 통제 가능 | 실행마다 새 폴더, 내용 해시 |
| 전역 지시 | `~/.codex/AGENTS.md`, `~/.claude/CLAUDE.md`, 프로젝트 지시 파일, 메모리 | 통제 가능(CLI 기능에 따라) | 격리 실행, 불가하면 부재 확인 실패로 실행 거부 또는 기록 |
| 도구·세션 | 도구 사용, 대화 기록, 자동 업데이트 | 통제 가능 | 끔, 버전 고정, 바뀌면 중단 |
| 출력 형식 | 자유 텍스트 vs 스키마 | 통제 가능 | 공급자 기능으로 스키마 강제 |
| 캐시 | 차가운/데워진 프롬프트 캐시 | 부분 통제 | 입력·캐시 읽기·캐시 쓰기 분리 기록, 워밍업 규칙 |
| 순서·시각 | 먼저/나중, 서버 부하, 속도 제한 | 부분 통제 | 항목마다 설정 순서 무작위화, 설정을 교차 배치, 시드 기록 |
| **숨은 시스템 지시** | CLI가 붙이는 기본 프롬프트 | **통제 불가**(CLI) | 결론을 CLI 조합으로 한정(명제 1), 가능하면 API 사용 |
| **공급자 무작위성** | 같은 입력에 다른 출력 | **통제 불가** | A/A 시험으로 잡음 바닥 측정(명제 2), 반복 |
| **모델 업데이트** | 실험 중 모델 교체 | **통제 불가** | 응답의 모델 식별자·시각 기록, 기준 항목 재실행, 변경 시 중단 |
| 채점 | 조정 세션의 판단, 판정자 선입견 | 통제 가능 | 결정적 채점(공준 5), 블라인드 판정 |

## 5. 귀결

**명제 1 (수단 한정성) — [논리적 귀결]**
에이전트 CLI로 얻은 비교 결과는 모델에 귀속될 수 없고, (CLI, 버전, 설정) 조합에 귀속된다.
*근거.* CLI는 관찰할 수 없는 시스템 지시와 도구 동작을 붙인다. 이 변인은 CLI마다 다르고 모델 변인과 함께 바뀌므로, 공준 1에 따라 두 효과를 분리할 수 없다. ∎

**명제 2 (잡음 바닥) — [정의에서의 귀결]**
두 설정의 결과 차이가 A/A 잡음 바닥 안에 있으면, 그 차이를 설정 차이로 해석할 수 없다.
*근거.* A/A 실행은 설정이 같으므로 그 불일치는 전부 통제 불가 변동이다. 설정 간 차이가 이보다 작으면 같은 변동으로 설명된다. 따라서 **모든 비교 실험은 A/A 시험을 포함해야 한다**(Kohavi et al., 2020의 온라인 실험 관행과 같은 이유). 이 원고에서는 안정성 벤치마크(7.5절)가 A/A 시험을 겸한다. ∎

**명제 3 (순서 교락) — [설계에서의 귀결]**
설정을 고정된 순서로 몰아서 실행하면, 캐시·시간 효과가 설정 효과와 교락된다.
*근거.* 순서가 설정과 1대1로 대응하면 순서의 효과를 설정의 효과와 구분할 수 없다. 항목마다 순서를 무작위화하고 설정을 교차 배치하면 순서 효과는 설정과 무관한 잡음이 된다. ∎

**명제 4 (정확도 상한) — [가정에서의 추론]**
정답이 사람 판정이면, 모델과 정답의 일치도는 판정자 간 일치도를 넘어 해석될 수 없다.
*추론.* 정답 자체가 판정자 간 불일치만큼 흔들리므로, 그 이상의 일치는 특정 판정자를 모사한 것과 구별되지 않는다. 따라서 판정자 간 일치도를 함께 보고해야 한다.

**명제 5 (비용의 비교 단위) — [정의에서의 귀결]**
공급자가 다르면 토큰 수로 비용을 비교할 수 없다.
*근거.* 공급자마다 토크나이저, 캐시 할인, 입력·출력 단가, 캐시된 입력을 토큰 수에 넣는지 여부가 다르다. 따라서 비용은 가격 정본으로 환산한 금액으로, 실패·재시도를 포함한 시도 건당 총비용으로 비교한다. ∎

## 6. 통제 절차

### 6.1 매니페스트 강제

실행기는 실행마다 부록 A의 칸을 기록하고, 통제 칸이 기대값과 다르면 **실행을 거부**한다. 거부도 기록한다.

### 6.2 사전 점검 (실행 전)

- 전역 지시 파일·메모리가 없는가(또는 격리 설정이 적용됐는가).
- CLI·SDK 버전이 등록값과 같은가, 자동 업데이트가 꺼졌는가.
- 작업 폴더에 과제 파일만 있는가.
- 출력 스키마 강제가 켜졌는가.

### 6.3 통제가 작동했는지 확인

| 확인 | 방법 | 실패 시 |
|---|---|---|
| **조작 점검** | 격리 폴더에 없는 파일·지시를 모델이 언급하는지, 매니페스트 통제 칸의 격리 항목이 참인지 확인 | 해당 실행을 무효 처리 |
| **A/A 시험** | 안정성 벤치마크(7.5절)의 반복 불일치로 잡음 바닥을 잰다 | 비교 해석에 잡음 바닥을 반영(명제 2) |
| **기준 항목 재실행** | 정답이 분명한 항목을 시작·중간·끝에 실행 | 결과가 바뀌면 표류로 보고 중단 |
| **음성 대조** | 설정만 이름을 바꾼 같은 설정 쌍 | 차이가 나면 실행기 결함 |

### 6.4 순서

항목마다 설정 순서를 시드로 섞고, 설정을 교차 배치한다. 반복 실행(7.5절)도 같은 입력을 연달아 몰아서 보내지 않고 다른 실행들 사이에 섞어 배치한다(명제 3).

### 6.5 블라인드

사람 판정자는 모델 이름과 AI 제안을 보지 않는다. 조정 세션은 채점하지 않는다.

## 7. 판단 기준

### 7.1 지표의 위계

| 위계 | 지표 | 쓰임 |
|---|---|---|
| 주 | 항목 단위 정확도, **위험 범주별 재현율** | 적격 판정 |
| 보조 | 균형 정확도, macro-F1, 혼동표 | 해석 |
| 민감도 | Cohen κ, Gwet AC1 (모델과 조정된 정답의 일치도) | 불균형 영향 확인 |
| 안정성 | 최빈 라벨 비율, 쌍별 불일치율, **위험 뒤집힘(놓침·거짓 경보)**, 반복 간 Fleiss κ (7.5절) | 잡음 바닥(명제 2), 위험 판단의 신뢰 |
| 운영 | 무효 출력 비율, 판단 유보 비율, 지연(중앙값·p90), 시도 건당 비용 | 비용 비교, 배포 판단 |

판단 유보(`unsure`)와 무효 출력은 비정답으로 계산하고, 응답률과 응답한 항목의 정확도를 따로 보고한다.

### 7.2 적격 조건

후보 m의 정확도 A_m, 기준 설정 A_b, 위험 범주 c의 재현율 R_{m,c}, 단측 신뢰하한 L(유의수준 0.025)에 대해 다음을 **모두** 만족하면 적격이다.

    L(A_m − A_b) > −δ,    L(A_m) ≥ a_min,    L(R_{m,c}) ≥ r_min,c

δ, a_min, r_min,c는 결과 전에 **허용 가능한 추가 오분류와 사람의 재검토 부담**으로 정한다. 기준 설정도 적격을 자동으로 보장받지 않는다.

### 7.3 선택 규칙

적격 설정 가운데 시도 건당 총비용의 추정값이 가장 낮은 설정을 고르고, 비용 차이의 불확실성을 함께 보고한다. 적격 설정이 없으면 결론은 "적격 설정을 확인하지 못했다"이다.

### 7.4 올리기 정책의 평가

경량 설정이 실패(무효 출력, 판단 유보, 반복 불일치, 시간 초과·토큰 상한)할 때 상위 설정으로 다시 부르는 정책은, 모델 비교와 섞지 않고 **별도의 정책 실험**으로 평가한다. 지표는 정책 전체의 정확도, 올라간 비율, 시도 건당 총비용이다.

### 7.5 반복 실행과 안정성 — 넓게 한 번, 일부를 깊게

한 번의 정답이나 오답은 하나의 관측값이다. 그러나 운영이 **후보당 1회 호출**을 전제로 한다면 주 성능도 1회 결과로 재야 한다. 그래서 실험을 두 층으로 나눈다.

```text
주 벤치마크 (Main)                     안정성 벤치마크 (Stability)
────────────────────────               ────────────────────────
N 후보 × 설정마다 1회                   층화 부분표본 n × 설정마다 5회 (주 실행과 별도)
- 후보 단위 정확도                      - 후보별 최빈 라벨 비율
- 위험 범주별 재현율                    - 쌍별 불일치율, 뒤집힘 후보 비율
- 실패율(무효·유보·시간 초과)            - 위험 뒤집힘: 놓침 방향 / 거짓 경보 방향
- 시도 건당 비용                        - Fleiss κ (반복 간, 우연 보정)
```

**다수결 금지.** 반복 결과를 다수결해 주 정확도를 만들지 않는다. 운영에서 없는 추론 기회를 주어 성능을 부풀리기 때문이다. 다수결 정책을 쓰고 싶다면 그것은 호출 수가 다른 **별도 정책**이며 7.4절처럼 따로 평가한다(다수결로 판정을 안정화하는 관행은 LLM 판정자 연구에서도 별도 정책으로 쓰였다; Zheng et al., 2023).

**지표 정의 (실행 순서와 무관하게).** 후보 i의 반복 라벨 k개(기본 k = 5)에 대해

- 최빈 라벨 비율 m_i = (가장 많이 나온 라벨의 수) / k — 5/5 완전 일치, 4/5 높은 일치, 3/5 이하 상당한 변동
- 쌍별 불일치율 d_i = 서로 다른 라벨인 실행 쌍의 수 / C(k, 2)
- 뒤집힘 후보 비율 = m_i < 1 인 후보의 비율
- **위험 뒤집힘**은 방향을 나눈다.
  - **놓침 방향:** 정답이 위험 범주인 후보에서, 반복 중 한 번이라도 비위험 범주 또는 `unsure`가 나온 비율(예: `different-role → correct`, `different-role → unsure`, `missing-kind → taste`). 사람 검토 누락이나 잘못된 승인으로 이어진다.
  - **거짓 경보 방향:** 정답이 비위험인 후보에서, 한 번이라도 위험 범주가 나온 비율. 사람의 불필요한 검토 부담으로 이어진다.
- 반복 간 Fleiss κ: 우연 일치를 뺀 반복 간 일치도.

**반복 횟수.** 기본 5회. 3회는 결과가 3/3·2/3·1/3로만 나뉘어 차이를 보기 어렵고, 10회 이상은 안정성이 주 질문이 아닌 한 비용 대비 정보가 적다.

**부분표본.** 주 벤치마크 후보에서 사전에 정한 시드로 뽑되, 정답이 위험 범주인 후보가 최소 개수 이상 들어가도록 **층화**한다(단순 무작위로는 드문 위험 범주가 거의 들어가지 않는다). n과 층별 개수는 사전 등록한다. 반복 5회는 주 벤치마크의 1회와 **별도로** 실행해, 주 결과가 반복의 영향을 받지 않게 한다. 기준 설정(gpt-6-sol)도 같은 방식으로 반복한다.

**다른 절과의 연결.**
- 안정성 벤치마크의 불일치는 **잡음 바닥**(명제 2)을 겸한다. 주 벤치마크에서 두 설정의 차이가 잡음 바닥 안에 있으면 설정 차이로 해석하지 않는다.
- 쌍별 불일치율은 올리기 정책(7.4절)의 "반복 불일치" 신호가 얼마나 자주 켜질지를 미리 추정한다.
- 안정성 벤치마크의 호출 비용은 시도 건당 비용에 넣지 않고 따로 보고한다.

**표본 수의 현실.** 주 벤치마크 후보 N개에 두 명 이상의 독립 판정을 붙이면 판정이 2N건 이상 필요하다(예: N = 500이면 1,000건 이상). N은 파일럿에서 판정 속도와 검정력 시뮬레이션으로 정한다.

### 7.6 통계

주 벤치마크의 비열등성은 항목 단위 쌍체 군집 부트스트랩의 차이 하한으로, 두 설정의 정오 차이는 McNemar로, 독립·비가중 비율의 구간은 Wilson으로 구한다. 가설 집합에 Holm 보정을 한다. 표본 수는 적격 조건 전체를 반영한 시뮬레이션으로 90% 검정력에 맞춘다. 중간 결과를 보고 표본을 늘리거나 멈추지 않는다. 안정성 지표의 구간은 후보 단위로 묶은 부트스트랩으로 구한다.
