# Pilot — where do misaligned `;` and `=` come from? (2026-09-26)

Alongside the new language engine work, we measured how far the tabular readability checker (the TypeScript AST-based `06_align-tables.ts`) catches `=` and `;` column misalignment across a private TypeScript application (src + scripts, 349 files). The checker ran from this plugin's single source; the target repository was only read.

## Method

1. Scan every file, measure the `=` and `;` columns of single `const/let/var` declaration rows, and collect runs of three or more contiguous same-shape rows with misaligned columns.
2. Cross-classify whether each run belongs to a group reported by the checker.
3. Read the runs left outside any group line by line and classify the cause.

## Results

| Category | Count | Meaning |
|---|---|---|
| Pure runs of 3+ rows | 62 | Alignment candidates from the checker's point of view |
| └ covered by checker groups | 53 | All already judged aligned (edits=0) — the scanner's false alarms came from mixed rows outside the group falling into the site range |
| └ not covered | 9 | Exhaustive review: all are refusals justified by the contract (below) |
| `;` misalignment audit across all files | one file | **Real drift the checker catches** — a file not re-locked after a recent edit |

Conclusions from reading the 9 uncovered sites line by line:

- **Mixed rows (several statements on one line)** — e.g. `const dir = this.artifactsDirectory(); await this.ensureDirectory(dir);`. Under the spreadsheet contract of one row = one statement, these are not table rows, so the checker is right to refuse them. Such lines are restructured into multiple rows by the readability workflow (human + inspector), not by the checker, and then locked.
- **Multiple declarators** — e.g. `const s = this.get(), heading = executionHeading(s);`. Likewise, one row holds several name–value pairs and cannot be one spreadsheet row. The checker skips mixed rows and **correctly locks runs of 3+ pure rows as separate tables** (confirmed at four sites).
- Most remaining visible misalignments are **2-row pairs**. Under the contract, two rows are promoted to a table only when the user confirmed the comparison is useful. The mechanism already exists: `06_align-tables.ts --file <file> --min-rows 2`.

## Conclusions

1. **The checker's `=`/`;` axis detection and alignment work correctly.** No missed case was found among pure runs of 3+ rows. No grid-kinds changes were needed.
2. Visible misalignment has three real causes: ① mixed rows and multiple declarators (need restructuring), ② 2-row pairs (need a promotion policy), ③ files not re-locked after edits (`misaligned=1` — caught immediately by the checker).
3. Recommended next step: run the `00_normalize-imports` → `06_align-tables --file` check loop across the repository to list drifted files, restructure mixed rows through the readability workflow, then lock them. Bulk `--write` requires separate user approval.

## Reproduction

```bash
cd <target repository>
bun <plugin>/skills/xxx/scripts/typescript/06_align-tables.ts --file <file>   # confirm misaligned=1
```

The run- and row-level classification used temporary measurement scripts that were not kept.
