# Codex Astra 공동 저자 검토 — 논문 초고 (2026-10-01)

검토자: Codex CLI 0.158, gpt-6-astra, 추론 high, 27,161토큰 (purpose: dev-review). 아래는 원문 그대로이며, 반영 결과는 `docs/paper/paper.md`에 있다.


현재 초고의 가장 큰 문제는 **정렬기의 유용성·안전성에 관한 주장과, 실제 본시험이 검증하는 모델 선택 문제가 일치하지 않는다는 점**입니다. 이번 보고서는 “사람 승인 기반 정렬 시스템에서 사용할 사전 분류기의 성능·비용 평가”로 중심을 좁히는 편이 설득력 있습니다. 아래 검토는 제공된 텍스트에 한정하며, 참고문헌의 서지와 인용 적합성을 외부에서 확인하지 않았습니다.

**1. 가장 심각한 약점 다섯 가지와 수정안**

**① 논문의 핵심 주장과 실험의 검증 대상이 다릅니다.**

서론은 수직 정렬이 코드 비교를 돕고, 문형 기반 분류가 기존 포매터의 한계를 해결한다는 이야기입니다. 그러나 본시험은 LLM의 판정 정확도와 비용만 측정합니다. 모델이 사람의 라벨을 잘 예측해도 정렬의 가독성 효과, 아홉 문형의 타당성, 엔진의 안전성은 입증되지 않습니다.

또한 “편집마다 증명”이라는 표현은 현재 제시된 런타임 검사보다 강합니다. 재파싱 성공이나 진단 동일성만으로 의미 보존을 보장할 수는 없습니다.

**수정안:** 이번 연구의 확인적 기여를 모델 선택으로 한정하고, 정렬기와 문형 체계는 실험 과제를 구성하는 시스템·설계 가정으로 명시하십시오. 가독성 개선을 주요 기여로 유지하려면 정렬 전후의 이해 정확도·소요 시간 등을 비교하는 별도의 개발자 실험이 필요합니다. 안전성은 “정의된 편집 제약과 사후 검사를 통과한 변경만 적용한다”로 바꾸고, 검사 계약을 부록에 완전히 기술하십시오.

**② 무엇을 맞혀야 하는지, 정답이 무엇인지 아직 정의되지 않았습니다.**

“다섯 판정”이라고 하지만 `correct`, `taste`, `different-role`, `missing-kind`와 `unsure`의 관계가 명확하지 않습니다. `taste`는 약속 위반인지, 허용 가능한 대안인지, 개인적 선호인지 불분명합니다. 하나의 후보가 `different-role`이면서 `missing-kind`일 가능성도 있습니다.

더 근본적으로, 승인된 약속 준수를 평가하면서 모델에 그 약속을 제공하지 않으면 모델 능력과 정보 부족을 혼동하게 됩니다. “공백 정렬을 좋아하는가”와 “주어진 규칙을 올바르게 적용하는가”는 다른 과제입니다.

**수정안:** 과제를 다음처럼 구체화하십시오.

> 입력은 미승인 패턴 후보의 구조 정보, 고정된 선정 절차로 추출한 예문 묶음, 적용할 프로젝트 약속이다. 출력은 명시된 판정 지침에 따른 범주이며, 사람 승인을 대체하지 않는다.

각 라벨에 필요조건·배제조건·경계 사례를 제공하십시오. 범주가 겹치면 다중 라벨로 바꾸거나 우선순위를 고정해야 합니다. `unsure`는 가능하면 실질적 정답 범주와 구분되는 **모델의 판단 유보**로 다루십시오. 모델과 사람에게 같은 규범 정보를 주되, 시험 항목의 최종 승인 상태는 숨겨야 합니다.

**③ 표본 단위와 배포 분포가 불명확하여 유효 표본 수와 가중치가 흔들립니다.**

8,093개는 탐지된 표의 수입니다. 모델이 유형마다 한 번 판정한다면 실험 단위는 그보다 훨씬 적으며, 현재 설명에서는 72개 조회 키와 어떤 관계인지도 불명확합니다. 같은 유형의 표를 수천 개 포함해도 독립적인 유형 판정이 수천 개 생기는 것은 아닙니다.

또한 자주 등장하는 표의 빈도와 **새로운 미승인 유형이 대기열에 들어오는 빈도**는 다릅니다. 전자로 가중한 정확도가 후자의 운영 성능을 나타낸다고 볼 근거가 없습니다. 같은 조회 키 안에서도 역할이 다를 수 있다면 유형별 단일 정답 자체가 성립하지 않을 수 있습니다.

**수정안:** 본시험 전에 다음을 확정하십시오.

- 판정 단위: 조회 키인지, 키와 예문 묶음으로 구성된 후보인지.
- 추론 대상: 현재 고정 코퍼스인지, 새로운 저장소의 후보인지.
- 가중치 대상: 표 발생량인지, 미승인 후보의 유입량인지.

현재 업무 흐름에는 **미승인 패턴 후보 한 건**이 자연스러운 단위입니다. 실제 대기열 분포를 추정할 자료가 없다면 후보 단위 정확도를 주 지표로 삼고, 코퍼스 표 빈도 가중 정확도는 보조 지표로 두는 편이 타당합니다. 동일 키 내부의 판정 일관성도 먼저 조사해야 합니다.

**④ 정답 구축과 사전 등록의 독립성이 부족합니다.**

규범을 만든 저자 한 명의 판정을 정답으로 삼으면 모델이 공유 가능한 규칙을 따르는지, 저자의 암묵적 취향을 모사하는지 구별하기 어렵습니다. 두 번째 판정자는 타당성 위협 절에 적어둘 사항이 아니라 본시험 설계의 일부여야 합니다.

또한 코퍼스, 문형 체계, 상위 20개 유형, 기존 모델 반응을 이미 살펴보았습니다. 이 자료를 단순히 “보류 세트”로 다시 명명해서는 독립성이 생기지 않습니다.

**수정안:** 최소 두 명이 모델 출력 없이 독립 판정하고, 합의 전 라벨과 이견 이유를 보존하십시오. 설계에 참여하지 않은 판정자를 포함하는 것이 좋습니다. 합의되지 않은 사례의 처리도 미리 고정해야 합니다.

이미 검토한 유형·예문·모델 출력은 모두 탐색 자료로 선언하십시오. 본시험 보류 자료는 새로운 자료에서 구성하거나, 기존 자료 중 실제로 접근하지 않은 부분임을 입증해야 합니다. 현재 보류 자료까지 이미 검토했다면 새로운 보류 자료가 필요합니다.

**⑤ 비열등성 검정, 검정력 계산, 최저비용 선택 규칙이 서로 연결되지 않습니다.**

McNemar 검정의 차이 탐지 검정력으로 표본 수를 정하는 것은 비열등성 목적과 일치하지 않습니다. 위험 범주별 재현율 하한을 통과하는 데 필요한 표본 수도 별도로 고려해야 합니다. 기준 모델보다 열등하지 않다는 사실만으로 절대 성능이 충분하다고 판단할 수도 없습니다.

아울러 여러 후보 중 가장 싼 설정을 선택하면서 다중성 처리, 비용 불확실성, 실패·재시도 비용, 아무 후보도 통과하지 못했을 때의 결론이 빠져 있습니다.

**수정안:** 후보의 적격 조건을 다음처럼 명시하십시오.

> 기준 설정 대비 비열등성, 절대 정확도 하한, 각 위험 범주의 재현율 하한을 모두 충족한 설정만 비용 비교 대상에 포함한다.

그 공동 통과 규칙에 맞추어 검정력을 계산하고, 후보 간 다중성 처리도 사전에 고정하십시오. 결론은 “평가한 설정 중 적격 조건을 만족하며 추정 비용이 가장 낮은 설정”으로 제한해야 합니다.

**3. 제목과 초록 수정안**

제목: **사람 승인 기반 코드 정렬을 위한 LLM 사전 판정: 성능 제약하의 저비용 설정 선택을 위한 사전 등록 연구**

초록:

프로젝트의 코드 정렬 약속을 유지하려면 정렬의 기계적 적용과 패턴의 적합성 판단을 구분할 필요가 있다. 본 연구는 사람이 승인한 패턴 데이터베이스와 공백 편집에 대한 보존 검사를 사용하는 결정적 정렬기를 연구 맥락으로 삼고, 미승인 패턴 후보를 분류하는 LLM 설정의 성능과 호출 비용을 평가하는 사전 등록 실험을 제안한다. LLM의 출력은 사람의 판정을 보조하며 자동 승인을 수행하지 않는다.

탐색 단계에서는 TypeScript·Python의 공개 저장소 8개에서 표 8,093개를 추출했다. 깊이를 제외한 조회 키 72개 중 빈도 상위 20개가 표 발생 건수의 96%를 차지했다. 이는 해당 코퍼스와 탐지기에 한정된 기술 통계이다.

본시험에서는 탐색 자료와 분리된 패턴 후보에 대해 고정된 지침으로 복수의 사람이 독립 판정하고, 사전 지정한 모델 설정을 동일한 입력 조건에서 비교한다. 적격 조건은 기준 설정 대비 정확도 비열등성, 절대 정확도 하한, 위험 범주별 재현율 하한이다. 표본 수와 분석은 유형 간 의존성, 반복 실행, 다중 비교를 반영하여 사전에 확정한다. 적격 설정 중 실패와 재시도를 포함한 후보당 기대 호출 비용을 비교한다. 본 연구의 결론은 지정된 후보와 평가 분포에서의 모델 선택에 한정하며, 정렬의 가독성 개선이나 일반적 의미 보존을 검증하지 않는다.

**5. Methods·Analysis에 추가할 구체적인 사전 등록 항목**

**가. 판정 과제와 정보 조건**

등록 부록에 입력·출력 예시, 전체 프롬프트, 라벨 정의, 경계 사례, 이견 처리 절차를 포함하십시오. 입력에 제공하는 코드 문맥의 범위와 예문 수, 예문 추출 방식도 고정해야 합니다.

사람과 모델이 동일한 약속 정보를 받는지 확인하십시오. 프롬프트 해시만으로는 충분하지 않습니다. 알려진 정답 사례와 모호한 사례로 출력 스키마와 지침 적용 가능성을 점검하는 파일럿을 수행하고, 해당 사례는 본시험에서 제외하십시오.

**나. 문형·조회 키 체계의 한계 측정**

“미대응 0” 외에 다음을 기록해야 합니다.

- 전체 파일·구문 중 탐지기가 지원하지 않거나 건너뛴 범위.
- 하나의 문형으로 확정할 수 없는 비율.
- 동일 조회 키 안에서 서로 다른 사람 판정이 발생하는 비율.

현재 탐지 결과만을 분모로 삼아 분류 체계의 완전성을 주장하면 순환적 평가가 됩니다.

**다. 표집·분할·제외 기준**

저장소 SHA, 파일 선택 규칙, 생성 코드·벤더 코드·테스트·예제의 포함 여부, 중복 제거 방법을 고정하십시오. “소스당 최대 400파일”은 선택 순서가 없으면 재현할 수 없습니다.

유형과 저장소를 모두 분리하려면, 여러 저장소에 같은 유형이 등장할 때의 처리 규칙도 필요합니다. 엄격한 이중 분리로 표본이 부족해지면 “새 유형 일반화”와 “새 저장소 일반화”를 서로 다른 평가로 정의하십시오.

모델 오답이나 낮은 확신을 이유로 항목을 제외해서는 안 됩니다. 부적격 항목은 모델 출력 확인 전의 규칙으로 결정하고, 제외 수와 사유를 공개해야 합니다.

**라. 사람 정답과 판단 유보**

복수 판정자의 독립 라벨, 합의 전 일치도, 범주별 혼동, 최종 조정 결과를 보존하십시오. Cohen κ와 Gwet AC1은 무엇의 일치도를 측정하는지 명시해야 하며, 정확도의 일반적 “민감도 분석”으로 두는 것은 불명확합니다.

권장하는 기본 분석에서는 모델의 `unsure`와 유효하지 않은 출력은 비정답으로 계산합니다. 추가로 응답률과 응답한 사례에서의 정확도를 보고하십시오. 실제 위험 사례에서 `unsure`가 나온 경우, 해당 위험 범주를 정확히 식별한 것으로 계산해서는 안 됩니다. 사람에게 넘긴 효과를 평가하려면 별도의 전달 지표가 필요합니다.

**마. 적격 조건과 비열등성 한계**

후보 \(m\)의 정확도를 \(A_m\), 기준 설정을 \(A_b\), 위험 범주 \(c\)의 재현율을 \(R_{m,c}\)라 하면 적격 조건을 다음처럼 고정할 수 있습니다.

\[
L(A_m-A_b)>-\delta,\qquad
L(A_m)\ge a_{\min},\qquad
L(R_{m,c})\ge r_{\min,c}\;\; \text{각 위험 범주에 대해}.
\]

여기서 \(L\)은 등록한 방법으로 계산한 단측 신뢰하한입니다. 각 조건의 가중 여부와 다중성 처리도 명시해야 합니다.

\(\delta\), \(a_{\min}\), \(r_{\min,c}\)의 수치는 현재 초고만으로 정당화할 수 없습니다. \(\delta\)는 경량 모델의 관측 성능에 맞춰 정하지 말고, 허용 가능한 추가 오분류와 사람의 재검토 부담을 근거로 정하십시오. 파일럿은 주로 불일치율·범주 비율·분산 추정에 사용해야 합니다. 사람 승인이 남아 있는 구조이므로 “위험”도 자동 코드 손상과 동일시하지 말고 실제 업무상 손실로 정의해야 합니다.

**바. 검정력과 신뢰구간**

권고하는 설계 목표는 단측 유의수준 0.025와, 사전에 지정한 대안 조건에서의 90% 검정력입니다. 이는 제안하는 설계값이며 기존 근거로 확정된 값은 아닙니다.

표본 수는 McNemar 차이 검정 대신, 실제 적격 조건을 반영한 계산이나 시뮬레이션으로 정하십시오. 특히 위험 범주마다 재현율 하한을 통과할 충분한 **정답 양성 사례 수**가 필요합니다.

같은 유형의 반복 실행을 독립 항목처럼 세지 않아야 합니다. 부트스트랩은 표집 단위와 의존 구조를 보존하도록 설계해야 하며, 저장소 간 일반화를 주장하려면 저장소 군집도 고려해야 합니다. 다만 저장소 8개만으로 군집 수준 불확실성을 안정적으로 추정하기는 어렵습니다.

Wilson 구간은 독립적인 비가중 이항 관측에 적용하는 경우를 명시하십시오. 가중 정확도나 군집화된 반복 관측에 그대로 적용해서는 안 됩니다. 72개 유형 전체를 조사한다면 고정 집합의 전수 평가와 새로운 유형에 대한 추론도 구분해야 합니다.

**사. 다중성·중단·실패 규칙**

확인적 후보, 비교 집합, 주 지표를 고정하고 Holm 보정을 적용할 가설 집합을 열거하십시오. 한 후보가 여러 조건을 모두 통과해야 하는 문제와 여러 후보 중 하나를 선택하는 문제를 구분해야 합니다.

본시험의 항목 수와 항목별 반복 횟수를 고정하고, 중간 성능을 보고 표본을 추가하거나 종료하지 않는다고 명시하십시오. 예산·기간 상한에 도달해 목표 표본을 확보하지 못하면 미완료로 보고해야 합니다.

시간 초과, 공급자 오류, 스키마 오류, 응답 거부, 컨텍스트 한도 초과에 대한 재시도 횟수와 채점 규칙도 필요합니다. 모델 버전이 바뀌면 실행을 보류하고 변경 사실과 재개 규칙을 기록해야 합니다.

**아. 비용과 최종 선택**

고정된 가격 기준일을 사용하고, **시도한 후보 한 건당 총 호출 비용**에 실패·재시도를 포함하십시오. 성공적으로 완료된 항목당 비용도 함께 보고하되 그것만으로 비교하지 마십시오. 캐시 사용 조건과 워밍업 비용 처리도 사전에 정해야 합니다.

적격 설정이 여러 개면 사전 지정한 비용 추정량으로 선택하고 비용 차이의 불확실성을 보고하십시오. 모든 설정이 부적격이면 결론은 “적격 설정을 확인하지 못했다”입니다. 기준 설정 역시 적격성을 자동으로 보장받아서는 안 됩니다.

**자. 시스템 안전성의 명세**

11개 불변식, S1–S4, A0–A12를 모두 공개하고 안전 조건과 정책 조건을 구분하십시오. 공백 변경에서 줄바꿈과 Python 들여쓰기를 허용하는지, 토큰 비교가 `INDENT`·`DEDENT`와 줄바꿈 의존 구문을 어떻게 다루는지 명시해야 합니다.

지원 언어별 파서·버전을 고정하고, 위치 정보를 제외한 구문 구조 비교 등 필요한 검사를 정의하십시오. 진단 동일성의 비교 기준, 검사 실패 시 원본 유지, 멱등성과 결정성의 검증 범위도 포함해야 합니다. 이러한 검사를 통과했다는 사실은 유용한 증거이지만, 일반적인 의미 보존의 형식적 증명으로 기술해서는 안 됩니다.
