# Advancing an incompatible checker pin

Use this branch only when the configured immutable checker cannot represent a confirmed new contract or detector shape. An ordinary formatting defect remains a source fix.

## Establish the mismatch

- Read the configured checker version/commit and its actual isolated result.
- Run the same unchanged source through the proposed checker. Record both identities, the exact differing group/axes and the user's accepted rule.
- Retain a regression that fails on the old implementation, passes on the new one, and preserves the closest excluded shape. Verify approval identities and no-write boundaries independently.
- Keep exclusions and input bytes intact. A different checker is justified by the demonstrated mechanism, not by the desired exit code.

For example, a new documented-data kind sees an entire eight-field record while an older checker splits at JSDoc and judges only an inner three-field fragment. Padding to the inner fragment would damage the accepted outer table. This is different from both checkers finding the same real column mismatch.

## Bootstrap an immutable reference

1. Freeze the proposed checker source. Complete its focused/full source checks and independent review. Record the old-checker incompatibility as an open delivery gate.
2. If local commits are already authorized, create the smallest reviewed source checkpoint needed to obtain an immutable commit. State the remaining pin verification in its evidence; this checkpoint is not completed publication.
3. Point the checker configuration at that exact commit and its real package version. Build from that Git tree, rather than a mutable working directory or an unrelated published package. Record tree and bundle hashes from the resulting checker.
4. Rerun the checker harness and the stable changed-file inspection using the new pin, including real violation and aligned controls. Confirm that exclusions did not change.
5. Verify the selected source bytes again. A commit alone does not change that source candidate; checker-configuration-only changes need the affected harness checks, not an unrelated host-matrix rerun. A shipped source change returns to source verification.

## Deliver

Record source verification and the subsequent pin/harness verification separately. Final diff, commit-object checks and remote confirmation cover the entire stack. Publish only after the new pin, controls and required reviews pass, under the user's existing commit/push authorization. Report any missing hosted/native checks without claiming they ran.
